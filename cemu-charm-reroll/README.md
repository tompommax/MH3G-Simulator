# お守りテーブル リロール（Cemu 用パッチ）

日本版『モンスターハンター3（トライ）G HD Ver.』（Wii U）を Wii U エミュレーターの Cemu で遊ぶ時に使う、グラフィックパック形式のパッチです。
お守りのテーブルを、お守りごと（または起動ごと）にランダムに選び直します。

> 非公式のファンメイドパッチです。株式会社カプコンとは関係ありません。ゲーム内の名称等の権利は各権利者に帰属します。

## できること

Cemu のグラフィックパックの画面で、次の 2 つから選べます。

| 選び方 | 動き |
|---|---|
| お守りごと（既定） | お守りが作られるたびに、テーブルを選び直します。どのテーブルのお守りも出るようになり、テーブルの区切りが無いのとほぼ同じになります。 |
| 起動ごと | ゲームを起動してから最初にお守りが作られる時に 1 回だけ選び直し、その起動中はそのテーブルからお守りが出ます。 |

- 選ぶのは普通のテーブル 12 種類のどれかで、どれもほぼ同じ確率（8.3% 前後）です。呪われたテーブル（5 種類）は選びません。
- クエストで拾ったお守りは、クエストの後の鑑定の時にまとめて作られます。選び直しもこの時に行われます。
- 「起動ごと」は、タイトルに戻ってセーブをロードし直しても選び直しません。テーブルを変えたい時は、ゲームを起動し直してください。選び直した後にセーブしないままロードし直すと、セーブに入っているテーブルに戻ります。

シミュレーターのお守りの自動計算と一緒に使う時は、「自動計算で使うテーブル」を「すべて」にして探してください（「お守りごと」なら、どのテーブルのお守りも出るため）。ただし「すべて」には、呪われたテーブルにしか出ないお守り（915 種類）も入っていて、これはパッチを使うと出ません。

## テーブルが固定される理由（元のゲームの仕様）

- お守りは、ゲーム全体で共通の乱数（x → 176x mod 65363）から作られます。
- この乱数の値はセーブデータに保存されていて、ロードすると元の値に戻ります。
- 65363 = 163 × 401 なので、掛け算だけで進むこの乱数は、最初に乗った周期から抜け出せません。この周期がテーブルです。キャラクターを作った時にテーブルが決まり、その後ずっと変わらないのはこのためです。
- もし 65363 が素数だったら、乱数は 1 本の大きな周期になり、テーブルという区切りはありませんでした。「お守りごと」は、それに近い状態を作ります。

## 対応している環境

- 日本版 モンスターハンター3（トライ）G HD Ver.（タイトル ID `0005000010104D00`）。ゲームの実行ファイルのチェックサムが `0x2ad22bd7` のものだけに当たります（Cemu の `log.txt` に `Loaded module 'mh3g_cafe' with checksum 0x2ad22bd7` と出ます）。チェックサムが違う版では、パッチが当たらないだけで、ゲームは普段どおり動きます。
- グラフィックパック形式 version 7 に対応した Cemu。2026 年 9 月時点の Cemu 開発版で動作を確認しています。
- 日本版は、正式版の Cemu 2.6 ではゲームの起動直後に止まります（このパッチとは別の問題です）。2026 年 7 月 12 日以降の開発版を使ってください。
- 実機（Wii U 本体）では使えません。

## 入れ方

1. [Releases](https://github.com/tompommax/MH3G-Simulator/releases/tag/charm-reroll-v1.0.0) から `MH3G_CharmTableReroll.zip` をダウンロードして展開します。
2. 中の `MH3G_CharmTableReroll` フォルダを、Cemu の `graphicPacks` フォルダの中に入れます。`graphicPacks` フォルダは、Cemu のメニュー「ファイル」→「Cemu フォルダを開く」で開くフォルダの中にあります。
   - リポジトリ一式をダウンロードした場合は、PowerShell で `cemu-charm-reroll/scripts/install.ps1` を実行しても、同じ場所に入れられます。
3. Cemu のメニュー「オプション」→「グラフィックパック」を開き、`Monster Hunter 3 Ultimate` → `Mods` → `Charm Table Reroll (JP 3G HD)` にチェックを入れます。選び方は、右側のプルダウンで変えられます。
4. ゲームを起動します（起動中なら一度終了して、起動し直してください）。

パッチが当たったかどうかは、Cemu の `log.txt` に次の行があるかで確かめられます。

```text
Applying patch group 'MH3G_CharmTableReroll_JP_HD' (Codecave: ...)
```

## 外し方

グラフィックパックのチェックを外して、ゲームを起動し直してください。
セーブに残るのは乱数の値だけなので、外した後は、最後に遊んだ時のテーブルに固定されます（最初のテーブルには戻りません）。

## 今のテーブルを確かめる（任意）

`tools` フォルダに、遊んでいる最中の Cemu のメモリを読み取り専用で読むスクリプトがあります。Windows と Python 3 で動きます。リポジトリの一番上のフォルダで実行してください。

```powershell
python cemu-charm-reroll/tools/charm_state.py
```

今のお守りの乱数がどのテーブルに乗っているかと、パッチがこの起動で選び直した回数・直近に選んだ値（8 個まで）を表示します。
テーブルの番号は [MH3G スキルシミュレーター](../README.md) と同じです。

```powershell
python cemu-charm-reroll/tools/predict_charm.py
```

パッチが直近に選んだ値のそれぞれについて、その直後に作られるお守りを、お守りの種類ごとに予測します。鑑定で出たお守りと見比べると、パッチが効いていることを確かめられます。

## 仕組み

お守りを作る関数の入口に、次の処理を足しています。

1. 「お守りごと」なら毎回、「起動ごと」なら起動してから最初の 1 回だけ、処理を続けます。
2. タイムベース（時間とともに増える CPU のカウンター）と今の乱数の値を混ぜた数を 65362 で割った余りに 1 を足して、1〜65362 の値を作ります。
3. 163 の倍数か 401 の倍数なら、1 ずつ足して外します（倍数は呪われたテーブルの周期に乗る値です）。
4. できた値を、お守りに使う乱数に書き込みます。

解析の詳しいメモ（アドレス、乱数の構造、セーブの中の位置、動作確認の結果）は [docs/ANALYSIS.md](docs/ANALYSIS.md) にあります。
