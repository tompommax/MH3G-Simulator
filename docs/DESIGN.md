## 1. スコープ

- 入力: 欲しいスキル（系統 + 発動ポイント、最大 10）、職業（剣士/ガンナー）、性別、レア度上限、武器スロット数、所持お守り一覧（プルダウン入力、お守りなしを含めるか）、マイナススキル回避、最大表示件数、除外防具
- 出力: 条件を満たす構成を「最終防御力 → 空きスロット合計 → 初期防御力」の降順で最大 N 件。テキスト出力（全件をファイル保存、1 件をコピー / 保存）
- 対象外: 生産素材・HR/村☆の入手時期。お守りの完全な実在性チェック（系統ごとの出現スキル・最大値・スロット上限までは絞るが、第 1・第 2 スキルの組み合わせまでは見ない）

## 2. データ（src/Mh3gSim.Core/Data、exe に埋め込み）

データ JSON が正本 (手で直す前提)。どのファイルも 1 件 = 1 行で、GameData が読み込み時にシミュレーター内部の形 (部位番号・可否フラグ・耐性配列) に変換する。

| ファイル | 1 行の内容 |
|---|---|
| armors.json | id (除外機能の識別。重複不可), part (頭 / 胴 / 腕 / 腰 / 脚), name, class (両方 / 剣士 / ガンナー), sex (両方 / 男 / 女), rarity, defense (初期), maxDefense (最終), slots, skills { 系統: ポイント } (胴系統倍化の部位は「胴系統倍化」を持つ), resist { 火, 水, 氷, 雷, 龍 } |
| decorations.json | name, slots, skills { 系統: ポイント }（主スキル + 副スキルのマイナス） |
| skills.json | 系統ごとのブロック。1 行 = 1 発動スキル { points (負はマイナススキル), name, description } |
| charms.json | categories: お守りの系統 (なぞ / 光る / 古びた / 風化した) ごとに鑑定後の護石の種類, スロット上限 (1 / 2 / 3 / 3), 第 2 スキルの有無, 第 2 スキルのマイナス側の下限。maxPoints: 1 行 = 1 スキル { skill, 系統名: 最大ポイント }（書いていない系統には付かない） |

- 読み込み時の検査 (違反はファイル名・行 / id・名前つきで DataLoadException、アプリは起動時にダイアログ表示): JSON の書き方、part / class / sex / resist の値、charms.json の列名が categories にあること
- 整合チェック (`DataValidator`、`tools/Mh3gSim.Bench --check-data`、`scripts/publish.ps1` が exe を作る前に実行): id・名前・系統の重複、スロット・レア度の範囲、初期 ≤ 最終防御力、スキル名が skills.json にあること、装飾品のプラススキルが 1 つ、お守りの系統ごとの値の範囲と種類名の重複

## 3. スキル計算の仕様

- 系統ポイント合計 = 防具 + お守り + 装飾品。胴系統倍化の部位は「胴防具 + 胴に入れた珠」のポイントを複製する（倍化部位が k 個なら胴側は (1+k) 倍）
- 発動: 正のポイントは閾値以上で最大の閾値のスキル、負のポイントは閾値以下で最小の閾値のスキル
- スロット: 各部位・武器・お守りの穴は大きさ 1〜3。1 つの穴に複数の珠を入れられる（3 穴 = 3 / 2+1 / 1+1+1）

## 4. 検索アルゴリズム

1. **候補の絞り込み（部位ごと）**: 条件で絞った防具を「要求系統ポイント + スロット数」が同じもの同士で 1 つの**クラス**にまとめ、探索はクラス単位で行う。
   - クラス内は「最終防御力・初期防御力・マイナスになり得る系統のポイント」がすべて同等以上の防具があれば劣る方を外し（パレート集合 = Members）、外したものは「同等品」表示に回す
   - 「マイナスになり得る系統」= 要求外で負のスキルを持ち、防具・お守り・珠の最悪値を足すと負のスキルの発動値に届き得る系統（マイナススキル回避 ON の時だけ比べる）
   - クラス A がクラス B を不要にする条件: 要求ポイント・スロットが同等以上 かつ B のどの防具にも A の中に上記の意味で同等以上の防具がある（同じ装飾品がそのまま入り、マイナスも増えず、防御力も下がらないため）
   - 胴系統倍化は 1 クラスとして必ず残す
2. **分枝限定法**: お守り → 胴 → 残り部位（候補の少ない順）の DFS。各ノードで以下の枝を切る
   - 防御力上限: 現在 + 残り部位の最大防御力 < 保持している N 件の最下位の最終防御力（同点は空きスロット・初期防御力で逆転し得るので切らない）
   - 到達可能性: 残り部位を最大限使っても届かない（珠のある系統は「1 スロットあたり最大ポイント」でスロット換算、珠の無い系統は残り部位の最大ポイント合計で判定）
   - 葉では、まず各クラスの代表でマイナスを気にせず装飾品が足りるかを判定（ほとんどの葉はここで落ちる）。足りた時だけ、マイナススキル回避 ON なら各クラスの Members から 1 つずつ選ぶ組み合わせを防御力上限で枝刈りしながら試し、負のスキルが出ない装飾品の組み合わせがある中で最上位のものを採る
   - 1 つのクラスの組み合わせにつき結果は 1 件（他の防具は「同等品」として表示）。上位 N 件は「最終防御力 → 空きスロット合計 → 初期防御力」の比較で入れ替える
3. **装飾品の割当（DecorationSolver）**: まだ要求に届いていない系統のうち先頭の 1 つを選び、その系統の珠で不足を埋める最小構成（無駄な珠を含まない個数ベクトル）を少ないスロット順に試す。珠を足すたびに未達の系統を選び直すので、珠の副スキル（マイナス）で一度満たした系統が下回っても追加の珠で埋め直せる（例: 匠と業物を両方要求した時の 匠珠 ⇄ 斬鉄珠 の打ち消し合い）。穴に収まるかは次式で判定する（穴 h1,h2,h3 / 珠 n1,n2,n3）
   - n3 ≤ h3、n2 ≤ h2 + (h3 − n3)、n1 + 2·n2 + 3·n3 ≤ h1 + 2·h2 + 3·h3
   - 残り容量 < Σ(不足ポイント ÷ その系統の 1 スロットあたり最大ポイント) の枝は切る。1 構成あたり探索ノード 20000 で打ち切り、打ち切りが起きた構成数を画面に「見落としの可能性あり」として表示する
   - 胴系統倍化がある時は、胴の穴に入れる珠の組み合わせを先に列挙してから残りを解く
   - 「マイナススキル回避」で負のスキルが発動した組み合わせは捨てて次を試す
4. **配置表示**: 珠を大きい順に「残り容量が最小で収まる穴」へ入れる（best-fit）

### 既知の制約

- 装飾品の割当はノード数上限で打ち切るため、非常に多くの珠を要する構成では解を見落とす可能性がある（見つかった解は常に正しい。打ち切り件数は画面に表示）
- 「同等品」はスキル・スロットが同じ防具の一覧で、差し替えた時にマイナススキルが出ないことまでは保証しない

## 5. お守り入力とテキスト出力

- お守り入力: 種類 → スキル1 → ポイント → スキル2 → ポイント → スロットの順に選んで「追加」。種類を選ぶと、その系統に付き得るスキルだけ・最大ポイントまで・スロット上限までを選択肢にする。第 1 スキルは + のみ、第 2 スキルは +最大〜-10。「種類を指定しない」は全スキル・+13〜-10・スロット 0〜3 (表に無いお守り用)。既存の保存データ (種類なし) は「指定なし」として読み込む
- 出力: 詳細欄と同じ書式。全件保存は先頭に検索条件 (スキル・職業・性別・レア度上限・武器スロット・マイナス回避・お守り候補) を付け、`========== No.n ==========` で区切る。文字コードは BOM 付き UTF-8
- 詳細・出力の武器スロットは、画面の現在の入力ではなく検索時の条件を使う
- 結果の右クリックでは、右クリックした行を「現在行」にしてからメニューを出す (コピー・保存・除外が対象の行に効く)

## 6. 検証

- `tools/Mh3gSim.Bench --brute`: レア度 1〜2 の全組み合わせを総当たりした最高防御力と、検索結果の先頭が一致することを確認（攻撃+体力、達人+採取、採取+高速収集）
- 既知の構成例（ガノスＺヘルム他 + 千里眼11/風圧2 お守り → 自動マーキング/心眼/ランナー/ボマー）が検索結果に含まれることを確認
- `tools/Mh3gSim.Bench --solver-test`: 匠 8 / 斬れ味 8 から 匠 10 / 斬れ味 10 へ、匠珠と斬鉄珠を併用しないと満たせないケースで解が見つかること（初期実装は見落としていた回帰テスト）
- `tools/Mh3gSim.Bench --brute`（マイナススキル回避込み）: レア度 1〜2 の総当たりと最上位の順位キー（最終防御, 空きスロット, 初期防御）が一致し、全結果が要求を満たし負のスキルが出ないことを確認（6 条件）
- 差分テスト: マイナスになり得る系統を全部比較軸に入れた低速版（厳密）とランダム 30 条件で最上位が一致。千里眼/剣術/スタミナ/爆弾強化の例では低速版の構成クラス 118 通りがすべて新版の結果（142 通り）に含まれる
- Codex レビュー（2026-09-23、別ベンダー）で出た 6 件: 同点の枝刈り・上位入替が第 2/3 キーを無視 / マイナス回避時に要求外ポイントを無視した候補圧縮で有効な防具を消す / 代表選びで初期防御力を無視 / 副スキルが打ち消し合う珠の見落とし / 打ち切りを「解なし」と区別しない / 胴充填候補の重複 → すべて修正済み（上記の仕様に反映）
- 速度: 2〜4 スキル・お守り 1〜2 個で 0.1〜0.4 秒（匠＋業物＋武器 3 スロットなど重い条件でも 0.4 秒前後）
- `tools/Mh3gSim.Bench --check-data`: 全データの整合 (§2)。1.1.0 の書き方変更では、変換前後で全件の意味が一致すること (往復変換) と、検索結果・総当たり照合が変換前と同じことを確認。わざと壊した 4 パターン (カンマの過不足 / 部位名 / スキル名 / お守りの系統名) でファイル名と行・防具名つきのエラーになること、アプリが落ちずにダイアログを出すことを確認
- 画面操作 (1.1.0): 種類を選ぶとスキル・ポイント・スロットの選択肢が絞られること、追加したお守りが種類付きで保存され検索に使われること、全件保存 (200 件・検索条件付き・BOM 付き UTF-8)、右クリックした行のコピー・除外が対象行に効くこと
