## 1. スコープ

- 入力: 欲しいスキル（系統 + 発動ポイント、最大 10）、職業（剣士/ガンナー）、性別、レア度上限、武器スロット数、お守り（装備するお守り 1 つをプルダウン入力 / なし / 自動計算。自動計算はテーブル指定可）、マイナススキル回避、最大表示件数、除外防具
- 出力: 条件を満たす構成を「最終防御力 → 空きスロット合計 → 初期防御力」の降順で最大 N 件。自動計算では「必要なお守り」ごとに最上位の構成 1 件。テキスト出力（全件をファイル保存、1 件をコピー / 保存）
- 対象外: 生産素材・HR/村☆の入手時期。お守り入力は選択肢の範囲までしか絞らない（実在しない組み合わせも入力できる。入力欄の下の「出るテーブル」で確かめられる）

## 2. データ（src/Mh3gSim.Core/Data、exe に埋め込み）

データ JSON が正本 (手で直す前提)。どのファイルも 1 件 = 1 行で、GameData が読み込み時にシミュレーター内部の形 (部位番号・可否フラグ・耐性配列) に変換する。

| ファイル | 1 行の内容 |
|---|---|
| armors.json | id (除外機能の識別。重複不可), part (頭 / 胴 / 腕 / 腰 / 脚), name, class (両方 / 剣士 / ガンナー), sex (両方 / 男 / 女), rarity, defense (初期), maxDefense (最終), slots, skills { 系統: ポイント } (胴系統倍化の部位は「胴系統倍化」を持つ), resist { 火, 水, 氷, 雷, 龍 } |
| decorations.json | name, slots, skills { 系統: ポイント }（主スキル + 副スキルのマイナス） |
| skills.json | 系統ごとのブロック。1 行 = 1 発動スキル { points (負はマイナススキル), name, description } |
| charms.json | お守りの作られ方 (§5)。rng { multiplier, modulus }、tables: 1 行 = 1 テーブル { table, seed }、kinds: 1 行 = お守りの種類 { kind, secondSkillThreshold, names [{ name, maxScore }], slotRows [[1 スロット, 2 スロット, 3 スロット] の判定値 × スロット値の行] }、skills: 1 行 = スキル表の 1 行 { kind, list (skill1 / skill2), index (表の中の番号 = 乱数で選ぶ番号), skill, min, max } |

- 読み込み時の検査 (違反はファイル名・行 / id・名前つきで DataLoadException、アプリは起動時にダイアログ表示): JSON の書き方、part / class / sex / resist の値、charms.json の skills の kind が kinds にあること・list が skill1 / skill2・index が 0 から抜けなく続くこと
- 整合チェック (`DataValidator`、`tools/Mh3gSim.Bench --check-data`、`scripts/publish.ps1` が exe を作る前に実行): id・名前・系統の重複、スロット・レア度の範囲、初期 ≤ 最終防御力、スキル名が skills.json にあること、装飾品のプラススキルが 1 つ。お守り: 乗数と法が互いに素 (乱数が初期値に戻る)、テーブル番号が 1 から連番・初期値が 1〜法-1 で重複なし、第 2 スキルの判定値 0〜100 (100 未満なら skill2 の表が必要)、護石の名前の maxScore が小さい順で最後はなし、slotRows の各行が 0 ≤ 1 ≤ 2 ≤ 3 スロットの判定値 ≤ 100、スキル表の重複なし、skill1 は 1 ≤ min ≤ max かつ min × 10 ≥ max (スロット値が 1 以上)、skill2 は min ≤ 0 < max。範囲が正しければ全テーブルのお守りを実際に作ってみる

## 3. スキル計算の仕様

- 系統ポイント合計 = 防具 + お守り + 装飾品。胴系統倍化の部位は「胴防具 + 胴に入れた珠」のポイントを複製する（倍化部位が k 個なら胴側は (1+k) 倍）
- 発動: 正のポイントは閾値以上で最大の閾値のスキル、負のポイントは閾値以下で最小の閾値のスキル
- スロット: 各部位・武器・お守りの穴は大きさ 1〜3。1 つの穴に複数の珠を入れられる（3 穴 = 3 / 2+1 / 1+1+1）

## 4. 検索アルゴリズム

1. **候補の絞り込み（部位ごと）**: 条件で絞った防具を「要求系統ポイント + スロット数」が同じもの同士で 1 つの**クラス**にまとめ、探索はクラス単位で行う。
   - クラス内は「最終防御力・初期防御力・マイナスになり得る系統のポイント」がすべて同等以上の防具があれば劣る方を外し（パレート集合 = Members）、外したものは「同等品」表示に回す
   - 「マイナスになり得る系統」= 要求外で負のスキルを持ち、防具・お守り・珠の最悪値を足すと負のスキルの発動値に届き得る系統（マイナススキル回避 ON の時だけ比べる）
   - クラス A がクラス B を不要にする条件: 要求ポイント・スロットが同等以上 かつ B のどの防具にも A の中に上記の意味で同等以上の防具がある（同じ装飾品がそのまま入り、マイナスも増えず、防御力も下がらないため）
   - 胴系統倍化は 1 クラスとして必ず残す
2. **分枝限定法**: お守り → 胴 → 残り部位（候補の少ない順）の DFS。各ノードで以下の枝を切る
   - 防御力上限: 現在 + 残り部位の最大防御力 < 保持している N 件の最下位の最終防御力（同点は空きスロット・初期防御力で逆転し得るので切らない）
   - 到達可能性: 残り部位を最大限使っても届かない（珠のある系統は「1 スロットあたり最大ポイント」でスロット換算、珠の無い系統は残り部位の最大ポイント合計で判定）
   - 葉では、まず各クラスの代表でマイナスを気にせず装飾品が足りるかを判定（ほとんどの葉はここで落ちる）。足りた時だけ、マイナススキル回避 ON なら各クラスの Members から 1 つずつ選ぶ組み合わせを防御力上限で枝刈りしながら試し、負のスキルが出ない装飾品の組み合わせがある中で最上位のものを採る
   - 1 つのクラスの組み合わせにつき結果は 1 件（他の防具は「同等品」として表示）。上位 N 件は「最終防御力 → 空きスロット合計 → 初期防御力」の比較で入れ替える
3. **装飾品の割当（DecorationSolver）**: まだ要求に届いていない系統のうち先頭の 1 つを選び、その系統の珠で不足を埋める最小構成（無駄な珠を含まない個数ベクトル）を少ないスロット順に試す。珠を足すたびに未達の系統を選び直すので、珠の副スキル（マイナス）で一度満たした系統が下回っても追加の珠で埋め直せる（例: 匠と業物を両方要求した時の 匠珠 ⇄ 斬鉄珠 の打ち消し合い）。穴に収まるかは次式で判定する（穴 h1,h2,h3 / 珠 n1,n2,n3）
   - n3 ≤ h3、n2 ≤ h2 + (h3 − n3)、n1 + 2·n2 + 3·n3 ≤ h1 + 2·h2 + 3·h3
   - 残り容量 < Σ(不足ポイント ÷ その系統の 1 スロットあたり最大ポイント) の枝は切る。1 構成あたり探索ノード 20000 で打ち切り、打ち切りが起きた構成数を画面に「見落としの可能性あり」として表示する
   - 胴系統倍化がある時は、胴の穴に入れる珠の組み合わせを先に列挙してから残りを解く
   - 「マイナススキル回避」で負のスキルが発動した組み合わせは捨てて次を試す
4. **配置表示**: 珠を大きい順に「残り容量が最小で収まる穴」へ入れる（best-fit）

### 既知の制約

- 装飾品の割当はノード数上限で打ち切るため、非常に多くの珠を要する構成では解を見落とす可能性がある（見つかった解は常に正しい。打ち切り件数は画面に表示）
- 「同等品」はスキル・スロットが同じ防具の一覧で、差し替えた時にマイナススキルが出ないことまでは保証しない

## 5. お守り (入力・作られ方・自動計算) とテキスト出力

- お守り入力: 装備するお守り 1 つを、スキル1 → ポイント → スロット → スキル2 → ポイントのプルダウンで入力する (入力欄の内容 = 装備中のお守り。一覧・追加は無い)。スキル1 が「（なし）」ならお守りなし (他の欄は選べない)。選択肢は charms.json の種類を区別せずに合成した範囲 (CharmLimits): 第 1 スキル = どれかの種類の skill1 の表にあるスキル・その max の最大、第 2 スキル = skill2 の表から同様に、マイナス側は min の最小 (-10)、スロットはスロット判定表で付き得る最大 (3)。第 1 スキルは + のみ
- 入力欄の下に、入力したお守りと同じスキル・ポイント・スロットの実在するお守りが出るテーブルと護石の名前を表示する (無ければ「どのテーブルにも出ません」)。自分のテーブルを調べる手がかりにする

### お守りの作られ方 (CharmGenerator)

- お守りの乱数 x ← multiplier·x mod modulus (176·x mod 65363)。テーブル = 乱数の輪で、テーブルごとの初期値から 1 周 (通常 5400、短いテーブルは 200 / 54) する。輪の各位置から、お守りの種類ごとに 1 つずつお守りが出る
- 1 つのお守りの作り方 (乱数を 1 回進めるごとに r とする): 第 1 スキル = skill1 の表[r % 表の長さ] → ポイント = min + r % (max − min + 1) → r % 100 ≥ secondSkillThreshold なら第 2 スキルあり: 第 2 スキル = skill2 の表[r % 長さ] → r % 2 == 1 ならプラス → ポイント = プラスなら 1 + r % max、マイナスなら min + r % (1 − min) (min〜0)。第 2 スキルが第 1 スキルと同じか 0 ポイントなら付かない (乱数は進んだまま) → スロット数
- スロット数: スロット値 v = floor(第 1 ポイント × 10 ÷ 第 1 スキルの max + (第 2 ポイントがプラスなら 第 2 ポイント × 10 ÷ 第 2 スキルの max)) (小数のまま足してから切り捨て)。slotRows の min(v, 行数) 行目の [t1, t2, t3] と r % 100 を比べ、t2 以上なら 2 (t3 以上なら 3)、そうでなく t1 以上なら 1、それ以外 0
- 護石の名前: スロット値 + 2 × スロット数 が names の maxScore 以下の最初の名前
- 全テーブル・全種類・全位置のお守りを作り、同じお守り (種類・スキル・ポイント・スロットが同じ) をまとめて出るテーブルを記録する (CharmCatalog。初めて使う時に作る、約 0.15 秒)

### お守りの自動計算 (CharmFinder)

- 候補: 実在するお守り (テーブル指定ならそのテーブルに出るもの) を「欲しいスキルの系統ごとのポイント + スロット数」に直した組み合わせ。欲しいスキルがマイナスのお守りは候補にしない (マイナスの無いお守りより弱いだけで、目標にならない)。欲しいスキル以外のスキルは見ない
- 出すもの: 候補のうち成立するもので、それより弱い (ポイント・スロットがすべて以下) 候補では成立しないもの = 最小限のお守り。それぞれ、そのお守りで組める最上位の構成を 1 件付け、構成の順位 (§4 と同じ) で並べる
- 成立はポイント・スロットが多いほど成立しやすい (単調) ので、全候補を 1 つずつ検索せず、系統 2 つの組 × スロット数ごとに「成立する最小のポイントの組」の境目を階段状にたどる (第 1 系統を 0 から増やしながら、成立する第 2 系統の最小値を上から下げていく。検索回数は両方の上限の和程度)。候補は境目のどれか以上なら成立。検索は防具の候補づくりを 1 回で済ませた Probe (最上位 1 件だけ保持) で、組ごとに並列に行う
- 装飾品探索の打ち切りで「見つからない」が出た時は、それを成立しない証拠として境目の推論に使わず、候補を 1 つずつ検索して最小のものを選ぶ (打ち切りの影響をその候補だけに留める。打ち切り件数は画面に表示)
- 結果ごとに、その条件を満たす実在のお守り (ポイント・スロットが条件以上) の種類・出るテーブル・種類数・条件に近い例 3 つを付ける
- 実在するお守りの一覧は起動直後に裏で作る (入力欄の下のテーブル表示は、できるまで「計算中」)。検索を中止した時は一覧が前回の結果のままなので、状態欄に「表示は前回の検索結果」と出す
- お守りのスロットは穴 1 つ、ポイントは欲しいスキルにだけ足す (欲しいスキル以外のスキルがマイナスで負のスキルが出る場合は見ない。画面・出力に注意書きを出す)
### 保存とテキスト出力

- お守りは 1 つしか装備できないので、入力も 1 つだけ。検索はそのお守り (なしならお守りなし) で行う。保存ファイル (charms.json) はお守り 1 つの配列 (なしなら空配列)
- 旧版で複数登録していた保存データは先頭の 1 つを読み込み、次に保存した時点で 1 つになる。旧版の "Type" (護石の種類) は読み込み時に無視する
- 出力: 詳細欄と同じ書式。全件保存は先頭に検索条件 (スキル・職業・性別・レア度上限・武器スロット・マイナス回避・お守り候補) を付け、`========== No.n ==========` で区切る。文字コードは BOM 付き UTF-8。自動計算では見出しのお守りを「自動計算 (テーブル)」とし、結果ごとに必要なお守り・出るお守りの種類・出るテーブル・例を付ける
- 詳細・出力の武器スロットは、画面の現在の入力ではなく検索時の条件を使う
- 結果の右クリックでは、右クリックした行を「現在行」にしてからメニューを出す (コピー・保存・除外が対象の行に効く)
